# Rinari CLI — Nuestra propia CLI con LLM

> **Para Hermes:** implementar con TDD estricto, task por task.

**Goal:** Una CLI propia tipo Codex/Claude Code que habla con los modelos locales del usuario (qwen3.6-27b vía vLLM/LiteLLM/llama.cpp), con modo REPL de chat y modo agente de código. **Identidad: Rinari** — asistente tsundere (español, kaomoji), basada en `SOUL.md` del perfil agenttesting, con comandos `rinari update`, `rinari sync`, `rinari identity`.

**Architecture:** Paquete Python 3.11 + uv. CLI con typer+rich (rendering streaming markdown), cliente OpenAI-compatible con httpx (streaming SSE), REPL con prompt_toolkit, historial en SQLite, y un loop agéntico con tool-calling nativo (las endpoints del usuario — vLLM y llama.cpp b9246+ — soportan tools API).

**Tech Stack:** Python 3.11, uv, typer, rich, httpx, prompt_toolkit, pytest, httpx.MockTransport (tests sin red).

**Endpoints del usuario (config inicial):**
- `casa` → http://192.168.0.3:8020 (llama.cpp, model id cualquiera)
- `net` → https://api.xainner.net (LiteLLM público, model `qwen3.6-27b`, key = LITELLM_MASTER_KEY)
- `sat` → https://api.xainner.com (vLLM FP8 2x3090, model `qwen3.6-27b`)

## Risks / Tradeoffs

- **Tool-calling en llama.cpp:** b9246+ lo soporta para Qwen, pero hay que verificar con el modelo real. Fallback: protocolo JSON-en-prompt (el modelo escribe JSON con tool calls).
- **vLLM tool calling:** Qwen3 soporta nativamente tools API — verificar en smoke test.
- **Windows subprocess:** `run_command` debe usar bash (git-bash) en Windows; usar `shell=True` con bash explícito.
- **prompt_toolkit en Windows:** funciona, pero testing del REPL es manual.
- **YAGNI:** sin RAG, sin MCP, sin multi-modelo en una sesión — solo lo pedido (A+B).
